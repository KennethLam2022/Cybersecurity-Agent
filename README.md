# Cybersecurity Agent

> 面向用户自有网络安全法规、国家标准、行业标准及其他专业文档的 RAG 智能问答系统

**当前版本：v1.0.0**

Cybersecurity Agent 是一个本地优先的网络安全知识库问答系统。项目将用户自行导入的网络安全法律法规、等保国标、关键信息基础设施安全要求、行业标准和组织内部安全管理资料整理为可检索知识库，通过混合检索、重排和大模型生成，为用户提供带依据的专业问答、资料查询和知识库管理能力。

> 系统适合用于资料查询、条款定位、制度理解、方案起草和内部知识辅助，不替代正式法律意见、监管认定、审计结论或渗透测试授权判断。对于知识库没有覆盖、检索依据不足或问题超出边界的场景，系统应明确说明无法确认，而不是编造结论。

## 核心能力

- **专业知识库问答**：围绕用户已导入的网络安全法律法规、国家标准、行业标准、等保、关基和其他安全资料进行问答，并尽量给出引用来源。
- **混合 RAG 检索**：使用 FAISS 向量检索、ChromaDB、BM25 关键词检索、RRF 融合、重排模型和父文档聚合，提高召回稳定性和答案可追溯性。
- **流式对话体验**：基于 FastAPI 提供 Web 聊天界面，支持 SSE 流式输出，降低长答案等待感。
- **知识库处理链路**：支持文档解析、清洗、去重、切片、父文档索引构建、FAISS/Chroma 索引重建与增量处理。
- **会话记忆与记录**：使用本地 SQLite 保存会话、评测、配置等运行数据，便于追问和后台统计。
- **模型配置管理**：后台可管理聊天、兜底、打分、Prompt 评测、Embedding、Reranker 等模型配置。
- **Prompt 版本与测试**：内置 Prompt 版本管理、测试用例、失败分析和修复流程，支持持续改进 Agent 行为。
- **评测与看板**：提供检索质量评测、端到端问答评测、评分卡和 ECharts 管理后台，用于观察系统质量变化。
- **基础安全控制**：管理路由支持 `X-Admin-Token` 校验，LLM API 地址包含 SSRF 白名单校验，模型密钥在具备加密条件时使用 Fernet 保护。

## 使用流程

首次使用时，不能只启动服务后直接提问。系统至少需要先完成模型配置和知识库建库，前台 Agent 才有可用的回答依据。

### 第一步：在后台配置后端模型

启动服务后打开管理后台：

```text
http://127.0.0.1:8000/admin
```

进入“后端模型”页面，按实际接入方式配置模型服务、模型名称、接口地址和 API Key。项目支持多个模型角色，建议按下面的职责配置：

| 模型角色 | 主要用途 | 配置建议 |
| --- | --- | --- |
| Chat | 前台 Agent 生成回答 | 优先选择中文理解、长上下文和指令遵循能力稳定的模型，例如服务商提供的 `DeepSeek V4 Flash` 或同等能力的快速模型 |
| Fallback | 主模型不可用时兜底 | 配置一个与 Chat 不同的可用模型，避免主模型限流或故障时整个问答链路中断 |
| Chunk | 文档清洗和结构化 | 选择成本可控、中文文本处理稳定的模型；规则切片仍由系统完成，模型主要用于文档处理辅助 |
| PromptEval | Prompt 测试和端到端评测 | 建议使用与 Chat 不同的模型，减少模型自评造成的偏差 |
| Embedding | 文档和用户问题向量化 | 选择服务商支持的中文或多语言 Embedding 模型；建库和查询必须使用同一个模型 |
| Reranker | 对召回结果进行重排序 | 必须配置。优先选择中文检索效果稳定的专用 Reranker；未配置时系统只能完成召回和 RRF 融合，不具备重排能力 |
| Jailbreak | 安全检测和回答复核 | 可选。需要更严格的安全检测时单独配置，不建议与 Chat 共用同一模型 |
| Scoring | 答案质量评分 | 可选。用于评测和质量分析，建议使用独立于 Chat 的模型 |

配置时请注意：

- `DeepSeek V4 Flash` 只是配置建议，不是所有模型服务商都使用相同的模型 ID。实际填写的模型名称必须以服务商控制台或模型列表为准。
- Embedding 模型需要同时支持文档和查询向量化。更换 Embedding 模型后，原有 FAISS、Chroma 和相关向量索引需要重新构建。
- 如果使用本地 Ollama Embedding，需要先自行安装并准备对应模型；不要直接照抄示例中的本地服务地址，具体地址以本机部署方式为准。
- API Key 只填写在本地或私有部署的后台配置中，不要写入 README、Git 提交或公开配置文件。
- 模型配置完成后，应在后台执行连接测试，确认 Chat、Embedding 和 Reranker 均可以正常调用；Reranker 未通过测试前，不应进入正式问答验证。

### 第二步：在“文档入库”导入知识资料

进入后台的“文档入库”页面，导入自行准备且具备使用授权的资料。网络安全场景通常包括：

- 国家法律、行政法规和网络安全相关法规
- 国家标准、国家标准相关实施指南
- 网络安全行业标准、通信行业标准
- 组织内部制度、管理办法和操作规范（仅建议用于私有部署）

文档入库通常按以下顺序执行：

```text
导入原始文档
  -> 文档提取与格式解析
  -> OCR 或格式转换（需要时）
  -> 内容清洗、去重与结构化
  -> 按标题、条款和段落切片
  -> 构建父文档与元数据
  -> 使用 Embedding 模型生成向量
  -> 写入 FAISS / Chroma 索引
  -> 检查入库状态并进行检索测试
```

建议先使用少量已确认来源和授权边界的资料进行入库验证，确认标题、条款号、版本日期和来源信息能够被正确保留，再批量导入。新增、替换或删除资料后，应重新执行相应的清洗和索引构建，并用条款定位、标准适用范围等问题验证检索结果。

公开仓库不附带法律法规、国家标准、行业标准、内部制度或其他 demo 文档。使用者需要自行准备资料，并自行确认资料的获取、复制、处理和使用权限。

### 第三步：在前台使用 Agent

完成模型配置、文档入库和检索验证后，打开用户问答页：

```text
http://127.0.0.1:8000/
```

此时可以进行条款定位、标准适用范围查询、多份资料对比、制度理解和基于已入库资料的初稿生成。建议先从能够在知识库中明确定位的问题开始，确认回答带有可核验来源后，再进行跨文档分析和复杂追问。

前台问答的运行时链路如下：

```text
用户提问
  -> 安全与边界预检
  -> FAISS / BM25 / Chroma 混合检索
  -> RRF 融合、Rerank 重排、父文档聚合
  -> 大模型基于检索片段生成答案
  -> 来源校验与输出过滤
  -> 用户追问 / 后台评测 / Prompt 优化闭环
```

## 快速开始

### 前置条件

- Windows 10/11
- Python 3.10 或更高版本；建议使用 Python 3.12
- Node.js 18 或更高版本；仅在需要运行 TypeScript 工作区脚本时使用
- 可用的大模型服务配置；本地或远程均可，具体以后台模型配置为准
- 如果使用本地 Embedding 或兜底模型，需要先启动相应的本地模型服务

### 本地启动

```powershell
git clone https://github.com/KennethLam2022/Cybersecurity-Agent.git
cd Cybersecurity-Agent
.\start-agent.bat
```

启动后在浏览器打开：

- 用户问答页：`http://127.0.0.1:8000/`
- 管理后台：`http://127.0.0.1:8000/admin`

也可以直接从 FastAPI 入口启动：

```powershell
cd packages\agent\src
python main.py
```

### 依赖安装

仓库中预处理模块声明了独立依赖：

```powershell
cd packages\preprocessor
pip install -e .
```

如果从空环境启动 Agent 服务，通常还需要安装 FastAPI、Uvicorn、Jinja2、HTTP 客户端、ChromaDB、FAISS、BM25、Jieba、LangChain 社区包等运行依赖。当前仓库未提供统一的 Python requirements 文件，建议后续补齐 `requirements.txt` 或 `pyproject.toml`，避免部署时依赖漂移。

### 首次使用建议

1. 先完成“后端模型”配置和连接测试，再进入“文档入库”。
2. 文档入库完成后检查 FAISS、Chroma 和父文档索引状态。
3. 用 3 到 5 个明确问题做冒烟测试，例如条款定位、标准适用范围、制度差异对比。
4. 再运行检索质量或端到端评测，确认召回、引用和答案稳定性。
5. 如果答案出现无来源扩写，优先检查资料版本、切片、Embedding 和检索参数，再调整 Prompt 或更换模型。

## 知识库范围

公开版仓库不附带知识库原文、清洗结果、向量索引或 demo 数据。用户需要自行准备具备使用授权的资料，并在本地完成解析、清洗、切片和索引构建。

推荐目录约定：

- `RAG_DATA/03_cleaned/`：清洗后的 Markdown 知识库，本目录被 `.gitignore` 排除，不会提交到远端。
- `RAG_DATA/04_vector_store/`：FAISS、Chroma 和父文档索引，本目录被 `.gitignore` 排除，不会提交到远端。

新增资料后，需要重新执行清洗、索引构建和检索评测。不要把未确认授权的法规汇编、国家标准、行业标准、客户资料、内部制度或付费文档提交到公开仓库。

## 回答边界

系统应当优先回答以下问题：

- 网络安全法律法规、国家标准、行业标准的条款查询与解释
- 等保、关基、数据安全、个人信息保护等制度要求的资料检索
- 多份标准之间的差异、对应关系和适用条件梳理
- 面向内部汇报、制度草案、整改建议的初稿生成
- 基于已入库资料的问答、引用和摘要

系统不应当直接输出以下内容：

- 未经授权的攻击、绕过、防护规避、漏洞利用操作步骤
- 没有知识库依据的监管结论、法律定性或审计结论
- 供应商价格、采购排名、实时政策变化等仓库资料无法覆盖的信息
- 把模型推测包装成标准原文或官方结论
- 要求读取 Cookie、Token、账号密码或其他敏感凭据的操作

兜底策略很简单：检索不到可靠依据时，直接说明“当前知识库未检索到足够依据”，并建议用户补充资料、缩小问题范围或转人工核验。

## 数据与安全

- 知识库原文、清洗结果和向量索引默认保存在本地目录中。

- 管理后台接口通过 `X-Admin-Token` 做基础访问控制。

## 开发与验证

常用命令：

```powershell
# 启动服务
.\start-agent.bat

# 运行 Python 测试
python -m pytest packages\agent\src\tests

# 检查 FAISS / Chroma 状态
python packages\preprocessor\src\check_faiss.py

# 运行 Node 工作区 lint
pnpm -r lint
```

评测入口主要包括：

- 检索质量评测：对比 FAISS-only、BM25-only、Hybrid、Hybrid + Rerank 的召回与 MRR。
- 端到端问答评测：观察上下文精确率、召回率、忠实度、相关性和幻觉风险。
- Prompt 测试：用固定测试集验证系统提示词调整是否带来实际收益。

上线前至少应通过三类检查：服务能启动、知识库能召回、答案能给出可核验来源。任何一个环节失败，都不应该进入正式使用。

# Cybersecurity Agent

> 面向网络安全法规、国家标准、行业标准与运营商安全资料的 RAG 智能问答系统

**当前版本：v1.0.0**

Cybersecurity Agent 是一个本地优先的网络安全知识库问答系统。项目把网络安全法律法规、等保国标、关键信息基础设施安全要求、通信行业标准和运营商安全管理资料整理为可检索知识库，通过混合检索、重排和大模型生成，为用户提供带依据的专业问答、资料查询和知识库管理能力。

> 系统适合用于资料查询、条款定位、制度理解、方案起草和内部知识辅助，不替代正式法律意见、监管认定、审计结论或渗透测试授权判断。对于知识库没有覆盖、检索依据不足或问题超出边界的场景，系统应明确说明无法确认，而不是编造结论。

## 核心能力

- **专业知识库问答**：围绕网络安全法律法规、国家标准、行业标准、等保、关基、运营商安全资料进行问答，并尽量给出引用来源。
- **混合 RAG 检索**：使用 FAISS 向量检索、ChromaDB、BM25 关键词检索、RRF 融合、重排模型和父文档聚合，提高召回稳定性和答案可追溯性。
- **流式对话体验**：基于 FastAPI 提供 Web 聊天界面，支持 SSE 流式输出，降低长答案等待感。
- **知识库处理链路**：支持文档解析、清洗、去重、切片、父文档索引构建、FAISS/Chroma 索引重建与增量处理。
- **会话记忆与记录**：使用本地 SQLite 保存会话、评测、配置等运行数据，便于追问和后台统计。
- **模型配置管理**：后台可管理聊天、兜底、打分、Prompt 评测、Embedding、Reranker 等模型配置。
- **Prompt 版本与测试**：内置 Prompt 版本管理、测试用例、失败分析和修复流程，支持持续改进 Agent 行为。
- **评测与看板**：提供检索质量评测、端到端问答评测、评分卡和 ECharts 管理后台，用于观察系统质量变化。
- **基础安全控制**：管理路由支持 `X-Admin-Token` 校验，LLM API 地址包含 SSRF 白名单校验，模型密钥在具备加密条件时使用 Fernet 保护。

## 使用流程

```text
用户提问
  -> 安全与边界预检
  -> FAISS / BM25 / Chroma 混合检索
  -> RRF 融合、Rerank 重排、父文档聚合
  -> 大模型基于检索片段生成答案
  -> 来源校验与输出过滤
  -> 用户追问 / 后台评测 / Prompt 优化闭环
```

## 快速开始

### 前置条件

- Windows 10/11
- Python 3.10 或更高版本；建议使用 Python 3.12
- Node.js 18 或更高版本；仅在需要运行 TypeScript 工作区脚本时使用
- 可用的大模型服务配置；本地或远程均可，具体以后台模型配置为准
- 如果使用本地 Embedding 或兜底模型，需要先启动相应的本地模型服务

### 本地启动

```powershell
git clone https://github.com/KennethLam2022/Cybersecurity-Agent.git
cd Cybersecurity-Agent
.\start-agent.bat
```

启动后在浏览器打开：

- 用户问答页：`http://127.0.0.1:8000/`
- 管理后台：`http://127.0.0.1:8000/admin`

也可以直接从 FastAPI 入口启动：

```powershell
cd packages\agent\src
python main.py
```

### 依赖安装

仓库中预处理模块声明了独立依赖：

```powershell
cd packages\preprocessor
pip install -e .
```

如果从空环境启动 Agent 服务，通常还需要安装 FastAPI、Uvicorn、Jinja2、HTTP 客户端、ChromaDB、FAISS、BM25、Jieba、LangChain 社区包等运行依赖。当前仓库未提供统一的 Python requirements 文件，建议后续补齐 `requirements.txt` 或 `pyproject.toml`，避免部署时依赖漂移。

### 首次使用建议

1. 启动服务后先进入管理后台，检查模型配置是否可用。
2. 检查知识库状态，确认 FAISS、Chroma 和父文档索引都已存在。
3. 用 3 到 5 个明确问题做冒烟测试，例如条款定位、标准适用范围、制度差异对比。
4. 再运行检索质量或端到端评测，确认召回、引用和答案稳定性。
5. 如果答案出现无来源扩写，优先调整 Prompt 与检索参数，而不是单纯更换模型。

## 知识库范围

公开版仓库不附带知识库原文、清洗结果、向量索引或 demo 数据。用户需要自行准备具备使用授权的资料，并在本地完成解析、清洗、切片和索引构建。

推荐目录约定：

- `RAG_DATA/03_cleaned/`：清洗后的 Markdown 知识库，本目录被 `.gitignore` 排除，不会提交到远端。
- `RAG_DATA/04_vector_store/`：FAISS、Chroma 和父文档索引，本目录被 `.gitignore` 排除，不会提交到远端。

新增资料后，需要重新执行清洗、索引构建和检索评测。不要把未确认授权的法规汇编、国家标准、行业标准、客户资料、内部制度或付费文档提交到公开仓库。

## 回答边界

系统应当优先回答以下问题：

- 网络安全法律法规、国家标准、行业标准的条款查询与解释
- 等保、关基、数据安全、个人信息保护等制度要求的资料检索
- 多份标准之间的差异、对应关系和适用条件梳理
- 面向内部汇报、制度草案、整改建议的初稿生成
- 基于已入库资料的问答、引用和摘要

系统不应当直接输出以下内容：

- 未经授权的攻击、绕过、防护规避、漏洞利用操作步骤
- 没有知识库依据的监管结论、法律定性或审计结论
- 供应商价格、采购排名、实时政策变化等仓库资料无法覆盖的信息
- 把模型推测包装成标准原文或官方结论
- 要求读取 Cookie、Token、账号密码或其他敏感凭据的操作

兜底策略很简单：检索不到可靠依据时，直接说明“当前知识库未检索到足够依据”，并建议用户补充资料、缩小问题范围或转人工核验。

## 数据与安全

- 知识库原文、清洗结果和向量索引默认保存在本地目录中。
- 会话、模型配置、评测记录等运行数据保存在本地 SQLite 或 `agent_data` 相关文件中。
- 管理后台接口通过 `X-Admin-Token` 做基础访问控制。
- LLM API 地址会经过白名单校验，降低 SSRF 风险。
- 模型密钥、数据库、向量索引和业务资料如果包含内部信息，不应提交到公开仓库。
- 当前仓库未看到统一的许可证文件，使用、分发或商业部署前需要先确认授权边界。

## 开发与验证

常用命令：

```powershell
# 启动服务
.\start-agent.bat

# 运行 Python 测试
python -m pytest packages\agent\src\tests

# 检查 FAISS / Chroma 状态
python packages\preprocessor\src\check_faiss.py

# 运行 Node 工作区 lint
pnpm -r lint
```

评测入口主要包括：

- 检索质量评测：对比 FAISS-only、BM25-only、Hybrid、Hybrid + Rerank 的召回与 MRR。
- 端到端问答评测：观察上下文精确率、召回率、忠实度、相关性和幻觉风险。
- Prompt 测试：用固定测试集验证系统提示词调整是否带来实际收益。

上线前至少应通过三类检查：服务能启动、知识库能召回、答案能给出可核验来源。任何一个环节失败，都不应该进入正式使用。

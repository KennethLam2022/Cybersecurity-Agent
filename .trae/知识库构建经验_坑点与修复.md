## 坑点1：LlmCleaner 截断超长文档

### 现象

Agent 对等保三级相关问题的回答**不肯定、不确定**，明明知识库里放着 GB/T 22239-2019（等保基本要求）和 GB/T 28448-2019（测评要求），但检索出来的来源置信度极低（0.01-0.19），甚至完全没命中。

### 根因

`batch_process.py` 的管道流程是：

```
原始PDF → OdlParser（解析为JSON + full_markdown）→ LlmCleaner（本地LLM清洗）→ 最终MD
```

问题出在 **LlmCleaner 环节**：
1. 本地 LLM（Ollama 上的模型）有**上下文窗口限制**（通常 8k-32k tokens）
2. 超长PDF（如 GB/T 22239-2019 原始 93页/80k字）解析后的 Markdown 远超上下文窗口
3. LLM 只清洗了窗口内的前几章，后面的直接丢弃
4. 输出的最终MD文件只有 15k-16k 字，**仅含第一级和第二级，第3-5级全部丢失**

### 影响范围

| 文件 | 原始大小 | 截断后 | 丢失内容 |
|------|:-------:|:------:|----------|
| GB/T 22239-2019 文本版 | 80,826字/93页 | 15,907字 | 第三级安全要求（全部） |
| GB/T 28448-2019 | 262,568字/291页 | 15,686字 | 第二-五级（全部） |
| GB/T 25070-2019 | 41,617字/51页 | 16,091字 | 第三-五级（大部分） |
| 1.2《GB/T 22239-2019》（重复版） | 同上 | 15,657字 | 同上 |

**共3份核心等保文档受影响，对应 Agent 4个等保相关问题的回答质量严重下降。**

### 修复方案

**方案A：跳过LlmCleaner，从JSON直接恢复（推荐）**

```python
# test_output 目录下有 OdlParser 输出的完整JSON（含 full_markdown）
# 直接读取 JSON 的 full_markdown 字段，做轻量清洗（去图片引用）后写回MD

def clean_markdown(md_text):
    """轻量清洗：只去掉图片标记，不做LLM截断"""
    lines = md_text.split("\n")
    cleaned = [l for l in lines if not l.strip().startswith("![") and "_images" not in l]
    # 合并连续空行
    result, empty = [], 0
    for line in cleaned:
        if line.strip() == "":
            empty += 1
            if empty <= 2: result.append(line)
        else:
            empty = 0; result.append(line)
    return "\n".join(result)
```

**方案B：如果 JSON 也不存在，从原始PDF用 pypdf 直接提取**

```python
import pypdf
reader = pypdf.PdfReader(pdf_path)
full_text = "\n\n".join(page.extract_text() for page in reader.pages)
# 同样只做轻量清洗，跳过LlmCleaner
```

**索引更新**：修复后的MD文件需要增量重新索引（使用 `add_doc_to_index.py`，支持去重）。

### 发现方法

1. **方法一**：对比 `test_output/` 中JSON的 `full_markdown` 长度与最终MD文件长度
2. **方法二**：在MD文件中搜索各级标题（"第三级/第四级/第五级"）检查是否完整
3. **方法三**：对话中 Agent 对明确存在的知识回答不肯定 → 很有可能是文档被截断

## 坑点2：Chroma compaction bug（已知问题）

### 现象

增量索引时 Chroma 报错：
```
chromadb.errors.InternalError: Error executing plan: Error sending backfill request to compactor: Error constructing hnsw segment reader
```

### 根因

Chroma 的 hnsw index compaction 机制有 bug（已知问题 #7090）。当增量添加数据触发 compaction 时，hnsw 段文件损坏。

### 解决方案

- **主库使用 FAISS**（检索器当前默认走 FAISS），避免依赖 Chroma
- Chroma 作为互备，出问题时跳过 Chroma 索引，不影响 Agent 运行
- 代码中加 try-except 保护：

```python
try:
    collection.add(...)
except Exception as e:
    logger.warning(f"Chroma 入库失败（已知compaction bug），跳过: {e}")
```

## 避坑指南（未来构建同类项目的规范）

### 1. 管道设计的核心原则

```
解析层（解析器）→ 清洗层（可选）→ 切片层（分块）→ 入库层（向量化）

关键点：
- 解析层输出必须作为缓存保留（JSON + full_markdown）
- 清洗层绝不能是单点故障——做了清洗就必须保留原始解析结果
- 切片和入库可以独立于清洗运行
```

### 2. LLM 清洗的安全阈值

| 文档类型 | 安全阈值 | 判断方法 |
|----------|---------|----------|
| 纯文本PDF（<50页） | ✅ 可用LLM清洗 | MD大小 ≥ JSON的60%即可 |
| 扫描版OCR PDF | ⚠️ 需检查 | 如果MD明显小于JSON的40%，说明截断 |
| **超长PDF（≥60页）** | **❌ 跳过LLM清洗** | 直接走轻量清洗（去图片/去空行） |
| 超大PDF（>200页） | ❌ 跳过LLM清洗 | 同上 |

### 3. 质量门禁（每次索引后自动检查）

在 `batch_process.py` 中增加后处理校验：

```python
def validate_output(md_path: str, json_path: str = None, threshold: float = 0.4):
    """自动检测MD文件是否被截断"""
    md_size = len(Path(md_path).read_text())
    if json_path and Path(json_path).exists():
        json_size = len(json.load(open(json_path))["full_markdown"])
        ratio = md_size / json_size
        if ratio < threshold:
            logger.error(f"⚠️ 疑似截断: {md_path} ({ratio:.1%})")
            return False
    return True
```

### 4. test_output 目录的用途

- 保留所有解析 JSON（含 `full_markdown` 字段）永不清除
- 作为**审计回溯的黄金标准**（任何时候都可以对比MD是否被截断）
- 修复时直接从中恢复，无需重新解析PDF

### 5. 文件命名规范

同一份文档的不同版本（如 `文本版` vs `OCR版`）注意区分：
- 索引时同名文件取最新修改时间的版本（`batch_process.py` 已实现）
- 但不同文件名版本（如 `GBT 22239...md` vs `1.2《GB_T 22239》.md`）都会入库，导致知识冗余
- 建议：**同一份标准只保留一个版本**，其余在入库前删除

### 6. 故障恢复流程

```
发现Agent回答质量差 / 检索不到已知文档
  ↓
检查知识库文件完整性（是否包含各级内容）
  ↓
对比 test_output JSON 确认截断
  ↓
从 JSON 或原始 PDF 恢复（跳过 LlmCleaner）
  ↓
add_doc_to_index.py 增量索引
  ↓
验证：重新提问对比回答质量
```

## 坑点3：max_depth=0 导致子目录文档未被扫描

### 现象

Agent 对 GDPR 相关问题回答不完整——只有域外适用指南和执法案例，**没有 GDPR 法规全文**。

### 根因

`source_map.json` 中 `01-国家法律` 类别的 `source_dirs` 指向：

```
D:\信息安全各类资料\1.常用网络安全标准（v1.5.1）\00、网络安全相关LAW
```

但该类别**没有显式设置 `max_depth`**，`batch_process.py` 中的 `scan_source_files()` 函数在 `source_map.json` 中读取 `max_depth`，未设置时默认为 `0`（只扫描根目录，不进入子目录）。

结果：
```
00、网络安全相关LAW\                  ← 根目录被扫描（✅ 33个文件）
├─ 4.个人信息保护法.pdf                ✅ 在库
├─ ...                                ✅ 在库
├─ GDPR专题\                           ❌ 子目录，被跳过
│   ├─ 欧盟通用数据保护条例(GDPR)中文版译文全文.pdf  ❌
│   ├─ 欧盟GDPR《一般数据保护法案》.pdf             ❌
│   └─ ...                                       ❌
├─ 2022年新发布的标准\                 ❌ 子目录，被跳过
└─ 2023年发布的标准\                   ❌ 子目录，被跳过
```

### 影响范围

| 缺失内容 | 所在子目录 | 关键文件 |
|----------|-----------|---------|
| **GDPR法规全文**（数据主体权利、跨境传输） | `GDPR专题/` | 4份PDF/DOC |
| 2022年发布的新国标 | `2022年新发布的标准/` | 36份PDF |
| 2023年发布的新国标 | `2023年发布的标准/` | 15份PDF |

### 修复方案

在 `source_map.json` 中为 `01-国家法律` 添加 `max_depth`：

```json
"01-国家法律": {
    "source_dirs": [
      "D:\\信息安全各类资料\\1.常用网络安全标准（v1.5.1）\\00、网络安全相关LAW"
    ],
    "max_depth": 1,    ← 加这一行
    "exclude_keywords": ["NIST", "美国国家标准与技术"],
    "description": "中国网络安全核心法律（含欧盟GDPR参考）"
  }
```

⚠️ `max_depth: 1` 会进入 **所有** 直属子目录（包括 `GDPR专题/`、`2022年新发布的标准/`、`2023年发布的标准/` 等）。如果只想进 GDPR 专题而不想引入其他子目录，需要加 `exclude_keywords` 过滤。

### 发现方法

检查 `source_map.json` 中每个类别的 `max_depth` 字段：

```python
python -c "
import json
sm = json.load(open('packages/preprocessor/src/source_map.json'))
for k, v in sm.items():
    depth = v.get('max_depth', '未设置(默认0)')
    print(f'{k}: max_depth={depth}')
"
```

## 附录：如何快速检查所有文件完整性

```bash
# 检查等保目录下每个文件是否包含各级别
python -c "
from pathlib import Path
base = Path('packages/MD_Cleaned/02-等保国标')
for f in sorted(base.glob('*.md')):
    text = f.read_text(encoding='utf-8')
    has_l3 = '第三级' in text
    has_l4 = '第四级' in text
    has_l5 = '第五级' in text
    status = '✅' if (has_l3 or '不需要第三级' in text) else '❌'
    print(f'{status} {f.stem[:45]:45s} {len(text):>6,}字  L3={has_l3}')
"

# 对比JSON与MD
python -c "
import json
from pathlib import Path
t = Path('MD_Cleaned/test_output')
m = Path('packages/MD_Cleaned')
for jf in sorted(t.glob('*.json')):
    try:
        jd = json.load(open(jf)); js = len(jd.get('full_markdown',''))
    except: continue
    # 匹配MD
    for md in m.rglob(f'{jf.stem.replace(\"_docling\",\"\").replace(\"_ocr\",\"\")}*.md'):
        ms = len(md.read_text()); ratio = ms/js

"
```

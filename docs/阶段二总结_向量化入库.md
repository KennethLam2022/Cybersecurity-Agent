## 技术方案

### 切片策略
- 按 `##` / `###` 标题分割 → 父文档 section
- 超过 256 字再按 `RecursiveCharacterTextSplitter` 切子 chunk
- chunk_size=256, chunk_overlap=25
- Chunk ID: `{文件名}__s{节索引}__{子索引}`
- Parent ID: `{文件名}__s{节索引}`（支持父文档检索）

### 向量化方案
- Embedding 模型：`quentinz/bge-small-zh-v1.5`（Ollama 本地部署）
- Chroma：`chromadb.PersistentClient` 直接管理，全量重建策略（避免 Rust HNSW compaction bug）
- FAISS：LangChain FAISS 增量追加，短路径存储（`%TEMP%/cyber_faiss`）

### 分批策略
- 20 份/批，6 批次跑完
- 每批 Chroma 全量重建（删旧库 + 所有文件重新 chunk + embed + 写入）
- FAISS 增量追加（仅新文件）

## 已知问题
1. **ChromaDB Rust HNSW compaction bug**：1.5.9 版本的后台 compactor 在 segment merge 时可能失败。当前采用全量重建规避，但最终读取时仍有 compaction 报错。FAISS 作为主检索库不受影响。
2. **Embedding 重复计算**：Chroma 全量重建和 FAISS 增量各自独立计算 embedding，每批约浪费 ~20s。可优化为共享 embedding 结果。

## 后续阶段：检索管道集成（2026-05-24 完成）

### 产出物
- `packages/preprocessor/src/retriever.py` — 正式检索管道

### 检索效果

# 二期非通用与运营商硬编码整改清单

> 记录日期：2026-08-17
> 目的：明确当前代码中仍偏“运营商/通信行业/非通用网络安全”的位置，二期开发时逐项改为网络安全通用型、可配置、可观测实现。

## 1. 整改原则

二期目标是建设“网络安全通用型 Agent”，不是“移动运营商专用 Agent”。因此：

1. 通用主干能力不得绑定运营商、通信行业、5G 核心网、BOSS/CRM 等单一行业场景。
2. 行业能力可以保留，但必须作为“行业扩展包”存在，例如通信、金融、医疗、政务、能源等。
3. 领域分类、检索 fallback、测试集、Prompt 示例、元数据映射、评分权重都应配置化。
4. 前台普通用户不再暴露 LLM 配置，模型配置只保留在后台，并等待二期 RBAC 接管。
5. Agent Evaluation 主干测试集必须是网络安全通用型；运营商/通信行业样例只能进入行业扩展测试集。

### 2.2 `agent.py` 空检索 fallback query 写死

文件：

- `packages/agent/src/agent.py:1481`
- `packages/agent/src/agent.py:1762`

现状：

```python
fallback_queries = [
    "等保定级 安全等级 系统分类",
    "应急响应 安全事件 处置流程 灾难恢复",
    "网络安全 安全防护 管理要求"
]
```

问题：

- fallback 只覆盖等保、应急、通用管理三类。
- 对数据安全、个人信息保护、APP 安全、云安全、密码、供应链、风险管理等领域不够公平。
- 这类 fallback 策略不应该硬编码在 Agent 主流程里。

二期整改：

- 移入配置文件或数据库表。
- 按领域 taxonomy 动态选择 fallback query。
- Agent Trace 中记录 fallback 原因、fallback 查询、是否有效。

建议配置：

```yaml
fallback_queries:
  default:
    - 网络安全 合规要求 管理措施 技术措施
    - 信息安全 风险评估 安全控制
  data_security:
    - 数据分类分级 数据安全 风险评估 生命周期
  privacy:
    - 个人信息保护 告知同意 最小必要 权利响应
  app_security:
    - APP 安全检测 隐私合规 权限 SDK
  incident_response:
    - 网络安全事件 应急响应 分级 上报 处置
```

## 6. 二期建议任务拆分

### P0：前台 LLM 配置下线

- 删除/隐藏 `index.html` 模型设置按钮。
- 删除前台配置弹窗。
- 前台不再调用配置保存、测试、刷新模型接口。

- 新增 `security_domains.yaml` 或 DB 表。
- 定义通用领域、别名、图标、排序、是否行业扩展。
- 替换 `metadata_filter.py`、`retriever.py`、`agent.py` 中固定 category 映射。

- 替换 System Prompt 中核心网、BOSS、CRM、5GC 等例子。

### P1：评测集拆分

- 建立通用主干评测集。
- 通信/运营商/5G 题迁移到行业扩展评测集。
- Agent Evaluation 总分默认只看通用主干。

### P1：Agent Trace 与观测

- 统一记录 Router、Retrieval、Conversation、Evaluation 的 step trace。
- 每次评测关联 Prompt 版本、模型配置、知识库版本、taxonomy 版本。

### P2：清理或归档 `agent-core` 旧内置行业数据

- 确认 TypeScript `agent-core` 是否仍被使用。
- 若未使用，归档或标注废弃。
- 若使用，替换为通用网络安全样例。

## 7. 验收标准

1. 前台用户端无 LLM 配置入口。
2. 通用主干代码中不再出现默认运营商定位。
3. 通信/5G/运营商样例只存在于行业扩展 profile 或历史归档中。
4. 检索 category、fallback query、领域图标、测试域不再硬编码在主流程代码里。
5. Agent Evaluation 默认测试集覆盖网络安全通用领域。
6. 运行报告能区分：
   - 通用主干分
   - 行业扩展分
   - 安全风险分
   - 过程轨迹分

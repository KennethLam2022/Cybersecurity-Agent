### 📐 评估体系总览（RAG 行业标准 → 落地计划）

基于行业标准 RAG 评估框架（RAGAS、AgentEval、RAG Triad 等），全流程质量监控分为 **5 个域**，覆盖从入库到回答的每个环节：

```
入库阶段                         检索阶段                         生成阶段
┌──────────────┐     ┌──────────────────────┐     ┌──────────────────────┐
│ 解析/清洗    │     │ Query Rewrite        │     │ LLM 生成             │
│ Chunking     │────→│ 向量检索(FAISS)      │────→│ 来源核验/引用标注    │
│ 索引入库     │     │ BM25 稀疏检索        │     │ 语义评分/越狱检测    │
│ (FAISS/Chroma)│    │ Reranker 重排序       │     │ 置信度校准            │
└──────────────┘     └──────────────────────┘     └──────────────────────┘
       │                       │                           │
       ▼                       ▼                           ▼
 域A: 入库质量           域B: 检索质量                域C: 生成质量
 域D: 运维监控（已有 OK）     域E: 端到端综合评估（新增需求）
```

### 域E — 综合质量评测（Quality Eval）✅ 全部完成

**需求来源**：每次重建索引/修改配置后，一键验证整个系统有没有退化。不是问"检索好不好"（域B）或"回答好不好"（域C），而是问"这次变更后，整体质量是升了还是降了"。

**使用场景**：
1. 重建 FAISS/Chroma 索引后 → 跑测试题 → 和上次对比，看评分是否下降
2. 换了 embedding 模型或 chunk 参数后 → 跑分验证
3. 每次发版前 → 一键 smoke test，防止退化上线

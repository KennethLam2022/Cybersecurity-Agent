### 记录 2：后端评测 LLM 模型配置
- **现状调查**：
  - `eval_e2e.py` 行 165：`llm = agent.llm if use_llm else None` —— 用的是 `agent.llm`（即主对话的 `chat` 卡 LLM）
  - Prompt 评测用的是独立卡片 `promptEval`（module_id="promptEval"），在管理后台"后端模型"Tab 中配置
  - `admin_model_preview.html` 行 250：该卡片名称为 `"Prompt 评测 LLM"` ⑧，icon 🧪，默认使用 deepseek-chat
- **问题**：综合质量评测（域B/C 评分）如果复用 chat 卡，会和主对话共用模型——chat 卡换成廉价模型时，评分质量会跟着降
- **改法**：
  1. 将卡片 *⑥* 从 "Prompt 评测 LLM" → **改名为"后端评测 LLM"**（因为它不只评测 Prompt，还要评测 RAG 质量）
  2. `eval_e2e.py` 改为读 `promptEval` 卡配置来初始化评分 LLM，不再用 `agent.llm`
  3. 涉及的修改文件：`admin_model_preview.html`（改名）、`main.py`（`prompt_test_run` 注释更新）、`eval_e2e.py`（改用独立 LLM）
- **注意**：Prompt 测试和 RAG 质量评测用同一个 LLM 卡片是合理的——都是"评测"场景，需要一致的推理能力

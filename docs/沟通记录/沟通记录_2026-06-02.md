## 对话 025 - 修复 FAISS≠Chroma 不一致（交换顺序 + 后置校验）

**时间**：11:10~11:15

### 内容
入库全部完成后，执行修复方案。

### 代码修改（incremental_index.py）
1. **交换写入顺序**：Chroma 先写 → FAISS 后写（原来 FAISS 先写，若 Chroma 失败则 FAISS 无法回滚）
2. **新增 `_validate_consistency()`**：每次增量索引完成后自动对比 FAISS 和 Chroma 数量
   - 若 Chroma < FAISS：从 FAISS 索引重建向量，直接补入 Chroma（不需要重新 embedding）
   - 若 FAISS < Chroma：从 Chroma 取向量，通过 `add_embeddings()` 补入 FAISS
   - 最终二次校验，仍不一致则告警

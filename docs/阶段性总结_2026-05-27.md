# 阶段性总结 — 网络安全移动运营商智能 Agent

> 时间范围：2026-05-23 ~ 2026-05-27（5天）
> 项目阶段：知识库构建 → 检索管道 → 前端页面 → Agent 对话 → 稳定性 → API 优化

---

## 一、项目总体目标

构建一个基于行业标准法规的**网络安全 RAG Agent**，能够回答等保、网安法、CII 关基、通信行业标准等领域的专业问题，支持**浏览器对话**（Jinja2 + SSE 流式 + 侧边栏）并保持**多轮上下文**，以 Web 服务形式对内开放。

## 三、架构演进

### 3.1 知识库管道（Day 1）

```
原始PDF → OdlParser(JSON + full_markdown) → LlmCleaner(本地LLM清洗) → MD文件
                                                                          ↓
                                                                Chroma(7,316) + FAISS(7,316)
```

### 3.2 检索管道（Day 1→2）

```
query
├── FAISS 召回(向量) ──┐
├── Chroma 召回(向量) ──┼── 去重合并 ── Reranker(BAAI/bge-reranker-v2-m3) ── top_k 结果
├── BM25 关键词检索 ────┘         ↓
                             父文档聚合(1,993条)
```

### 3.3 Agent 前后端架构（Day 2→5）

```
用户(浏览器 Jinja2模板 / SSE流式)
  ↓ HTTP / SSE
main.py (FastAPI + Jinja2 + SSE)     ← 完整版前端(05-24)
  ↓                        或
api.py (FastAPI + HTTP直连)          ← 轻量版API(05-27)
  ↓
CyberAgent (agent.py)
  1. Query改写: 口语→关键词 (30/30触发)
  2. 检索: FAISS+Chroma+BM25 → RRF融合 → Reranker → 父文档聚合
  3. Prompt装配(E.5三层架构):
     System Prompt → 用户背景(跨会话记忆) → 参考资料(TOP-10截断40K) → Example(2个) → 压缩历史(最近5轮) → 当前问题
  4. LLM生成: SiliconFlow MiniMax-M2.5
     ↓ 失败
     Ollama qwen2.5:7b兜底
  5. 答案自检: LLM核查→删除无依据结论(如"建议使用Splunk")
  6. 跨会话记忆提取: 角色/标准 → 存入session_memory
  ↓
返回: answer + sources + conversation_id
```

### 3.4 稳定性架构（Day 3）

```
SiliconFlow(限流→熔断→重试×2) → 失败 → Ollama qwen2.5:7b兜底 → 全失败 → 友好拒绝
```

| 组件 | 参数 | 行为 |
|:----|:-----|:-----|
| 令牌桶限流 | capacity=10, fill_rate=2/s | 防429 |
| 熔断器 | 连续3次失败→OPEN 60s→HALF_OPEN→恢复 | 快速避让 |
| 重试 | 2次, 指数退避+jitter | 仅对timeout/429/5xx |
| Ollama兜底 | qwen2.5:7b | 可用时自动降级 |
| Rerank熔断 | 连续3次失败→跳过rerank→退回双库排序 | 独立熔断器 |

**规则**：超长PDF(≥60页)跳过LLM清洗，走轻量清洗(去图片/去空行)

### 5.2 等保1.0旧版标注 + 旧草案移除

| 操作 | 文件数 | 详情 |
|:----|:------:|:-----|

| 全量重建索引 | 109份/6,729 chunks | 含版本警告+过滤生效 |

### 5.3 ChromaDB Compaction Bug（坑点2）

- **根因**：Rust HNSW compactor pickle float/int 序列化不匹配
- **Workaround**：`hnsw:sync_threshold=100000`（大于总嵌入数，compactor永不运行）
- **当前状态**：FAISS 为主库，Chroma 为互备

## 六、Prompt 演进

| 版本 | 日期 | 核心变化 |
|:----:|:----:|:---------|
| v0 | 05-24 | 3行通用原则 → 无角色、无约束、无示例 |
| v1 | 05-24 | 42行三层架构：角色+约束+Context+CoT+One-shot → 输出思考过程表 |
| v2 | 05-24 | 删除思考过程，改为"核心结论→详细分析→操作提醒"；引用带文档名 |
| v3 | 05-24 | 引用格式加强制约束 + 5条回答原则 + 2个One-shot |
| **v4** | **05-25** | **7项改动：等保2.0修正 + 置信度 + 7条回答原则 + 编造红线 + 逻辑一致 + 2个One-shot** |

**当前 Prompt 核心要素**：
- 角色定位：运营商网络安全管理专家
- 5个能力领域 + 明确不做范围
- 7条回答原则（严格基于文档、区分红线/优化、直白接地气、整改方案、操作提醒、逻辑一致、编造红线）
- 输出格式：`【思考过程】→ --- → 最终回答`
- 来源标注格式：`[来源N: 文档名 / 章节]`
- One-shot示例：等保技术 + 网安法义务（均含思考过程）

## 九、关键决策记录

| 决策 | 选型 | 原因 |
|:-----|:-----|:------|
| 向量库 | Chroma + FAISS 双库互备 | Chroma compaction bug，FAISS为主库 |
| 嵌入模型 | Ollama quentinz/bge-small-zh-v1.5 | 中文语义好、本地运行 |
| LLM | SiliconFlow MiniMax-M2.5 | 中文能力好、API稳定 |
| Reranker | SiliconFlow BAAI/bge-reranker-v2-m3 | 精排质量高，失败降级纯向量 |
| 兜底 | Ollama qwen2.5:7b | 本地7B模型，API失败时可用 |
| Web框架 | FastAPI | 轻量、高性能、自动文档 |
| 对话存储 | SQLite | 零依赖、嵌入式、够用 |
| 自检方式 | 单LLM自检(后处理) | 不改生成逻辑，只做质量门禁 |
| 历史窗口 | 5轮完整 + 6轮起压缩 | 平衡上下文质量与token成本 |



# 电信网和互联网 API 数据安全技术要求和测试方法

**标准编号：** YD/T 4248-2023

## 概述

本文件规定了电信网和互联网API（应用程序接口）数据安全的技术要求，并提供了相应测试方法、判定准则等。

本文件适用于电信网和互联网API相关的开发者、运营者及专业测评机构开展API数据安全测试工作，为提升API数据安全水平，强化测试能力、健全技术手段提供指引和依据。

本文件不适用于操作系统接口、硬件接口。

## 术语、定义和缩略语

### 3.1 术语定义

**3.1.1 应用程序接口 application programming interface**

一组预先定义好的功能，开发者可通过该功能（或功能的组合）便捷地访问相关服务，而无需关注服务的设计与实现。

[来源：JR/T 0185-2020,3.1]

**3.1.2 会话令牌 token**

交互会话中证明自身的唯一身份标识符，可用于控制用户访问对象及执行相关操作的权限。

**3.1.3 开放应用程序接口 OpenAPI**

针对HTTP API的标准的、与编程语言无关的接口规范描述。

**3.1.4 模式 schema**

对API的接口和返回数据的类型、结构等信息的规范化描述。

**3.1.5 日志 log**

对设备或软件在运行过程中对其状态变化、操作及异常等进行的记录。

**3.1.6 异常行为 abnormal behavior**

针对数据所进行的异常的、不符合管理要求的、与预期不符的访问和利用的行为，包括并不限于对数据超频次访问、越权访问、绕行访问、非常规时间访问等。

**3.1.7 重要数据 key data**

一旦遭到篡改、破坏、泄露或者非法获取、非法利用，可能危害国家安全、公共利益的数据。

注:重要数据不包括国家秘密和个人信息，但基于海量个人信息形成的统计数据、衍生数据有可能属于重要数据。

## 安全技术要求

### 5.1 身份认证

#### 5.1.1 认证机制

应设置API用户身份认证机制，通过如密钥、令牌、证书、静/动态口令、OIDC等手段实现有效的用户身份验证。

注：用户指API调用方，如网站、应用程序等。

#### 5.1.2 安全策略

- a) API身份认证机制应具备口令复杂度策略，限制或禁止常见弱口令。
- b) API身份认证机制应具备身份认证操作锁定策略，对错误尝试次数进行限制。
- c) API身份认证机制应具备凭证有效期策略，要求定期对静态身份凭证进行修改。

### 5.2 接入授权

#### 5.2.1 授权机制

应具备API用户授权机制，并基于不同用户身份分配其可访问的服务、资源及可执行操作。

#### 5.2.2 会话管理

宜具备API访问会话管理机制，当用户会话过期或被放弃后，应及时锁定或注销用户并终止会话。

### 5.3 访问控制

#### 5.3.1 粗粒度访问控制

应具备针对未授权访问的识别和阻断能力，实现基于如访问时间、访问次数、用户IP等要素的粗粒度API访问控制。

#### 5.3.2 细粒度访问控制

- 宜通过ACL、RBAC等技术，实现基于如签名、时间戳、黑白名单等机制的细粒度API资源访问控制。

#### 5.3.3 令牌添加变量

应对API会话令牌等重要身份验证凭证进行添加变量操作，以防范重放、彩虹表碰撞等攻击。

#### 5.3.4 二次认证机制

涉及重要数据或个人信息的API，宜部署基于动态口令、oAuth（2.0及以上）等技术的二次认证机制。

### 5.4 数据传输

#### 5.4.1 请求参数校验

宜部署具备请求参数（如名称、参数类型、取值范围等）校验能力的API管控机制，包括但不限于WAF、API网关、数据层防护工具、代码层过滤配置等。

#### 5.4.2 数据资源安全

宜对API请求参数的规则、配置、URL等进行转义编码，避免关键地址、参数、字段泄露或存在歧义。

#### 5.4.3 安全传输策略

涉及重要数据或个人信息的API，应在数据传输中采用如加密、签名等手段对关键参数、数据内容等进行保护。

### 5.5 数据脱敏

#### 5.5.1 脱敏能力

涉及重要数据或个人信息等的API，宜部署数据脱敏工具并根据API功能及用户配置相应脱敏策略，以实现返回数据有效脱敏。

#### 5.5.2 脱敏有效性

API返回数据脱敏效果应与脱敏规则一致，确保数据脱敏的有效性、真实性、高效性和多样性。

注：数据脱敏要求可参考电信网和互联网数据脱敏相关标准。

### 5.6 数据筛选

#### 5.6.1 返回数据筛选

宜根据API功能及数据类型对返回数据类型、格式等进行筛选，避免返回数据量及数据内容超出API设计要求。

#### 5.6.2 差异化管控

宜根据API涉及的数据类型及数据分类分级情况对接口进行梳理，形成差异化管控，如差异化访问控制、身份认证机制、数据传输协议等。

注：数据分类分级相关要求可参考电信和互联网行业数据分类分级方法系列标准。

#### 5.6.3 重要数据识别

涉及重要数据或个人信息等的API，宜部署管控机制对返回内容进行识别并设置有效的告警、阻断策略。

### 5.7 攻击防护

#### 5.7.1 自动攻击防护

- a) 应具备同一用户或IP地址认证失败重试次数的限制，防范针对API的暴力破解攻击。
- b) 应具备对爬虫或扫描器等的数据爬取行为的监测识别能力，防范针对API的自动化数据爬取。
- c) 应具备对API访问速率和连接数管控机制，防范针对API的DDoS攻击。

#### 5.7.2 基于 API 模式的攻击防护

- a) 对API请求，应建立基于OpenAPI模式规范的安全防护机制。
- b) 对基于XML SOAP的API请求，宜建立基于WSDL模式规范的安全防护机制。

#### 5.7.3 数据传输防护

- a) 应对API远程数据传输采用TLS/TLCP加密技术，确保请求真实性，防范嗅探攻击、数据篡改等。
- b) 宜根据API功能及涉及数据类型通过安全管控工具、系统、平台等实现对数据传输行为的监控，防范非法访问、攻击行为等。

#### 5.7.4 注入攻击防护

应防范针对API的注入漏洞攻击，如通过API参数实现的SQL注入漏洞、命令注入漏洞、LDAP注入漏洞等。

### 5.8 安全监测

#### 5.8.1 异常行为监测

应形成正常API访问行为基线，针对如高频登陆尝试、爬虫访问、非工作时间访问、访问源IP地址异常、特权账号登陆、访问频次超标、批量下载等异常访问行为进行监测、记录，并阻断高危异常访问。

#### 5.8.2 特权账号监测

宜对API特权用户行为进行监测、记录，防范特权用户滥权操作。

#### 5.8.3 合作方访问监测

宜对API合作方用户异常行为进行监测，防范合作方用户越权操作。

### 5.9 进退网管理

#### 5.9.1 进网管理

应具备API上线审核机制，确保在满足安全要求的情况下进行审核发布并记录形成API资产清单。

#### 5.9.2 退网管理

应具备API下线审批制度并根据API关联情况进行退网管理，对于具有深度关联的API，宜根据关联层次逐层通知相关API使用方，并设定合理下线时限。

### 5.10 安全审计

#### 5.10.1 日志记录

- a) 应对API的访问、操作、告警等进行完整的日志记录，日志信息如请求IP、用户名、时间、请求API、请求内容、响应结果等。
- b) 日志宜记录API访问信息，如访问用户IP,登录令牌，权限级别、访问时间等。
- c) 日志宜记录API操作内容信息，如操作对象、请求方式（POST、PUT）、响应时间等信息。
- d) 日志宜记录API返回结果信息，如返回数据格式、执行成功与否、是否包含操作风险、是否包含重要数据等。

#### 5.10.2 日志审计

应对定期对API日志进行安全审计，确保日志完整性和可用性并形成审计报告。

#### 5.10.3 日志溯源

日志内容应直接或间接含有数据泄露源头、途径、类型、规模等信息，满足对与API相关的数据泄露事件的溯源需求。

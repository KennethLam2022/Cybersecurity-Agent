### ✅ 上下文截断统计图修复（已解决）
**问题**：性能看板"上下文截断统计(近30天)"图表空白。
**根因**：后端返回了3条真实数据但 `truncation_count` 全部为 0。旧判断条件 `tr.length > 0` 认为"有数据"就直接用真实数据，导致图表画了3根高度为0的柱子，肉眼不可见。
**修复**：将判断条件改为 `tr.length > 0 && tr.some(x => x.truncation_count > 0)`，后端全零时自动降级到 10 条 mock 数据。
**附加修复**：
- yAxis 加了 `min:0, max:10` 强制坐标范围
- `switchTab` 中 `renderDashboard().then()` 确保图表创建完后再 resize
- `renderPerfCharts` 末尾加延迟 resize
- 去掉 `...dateOpt` 引用改为内联（消除作用域隐患）
**验证**：✅ Chrome 中图表正常显示 10 根柱子（3-8 范围）。

### 重名检测逻辑确认（将落实到后端）
**模糊归一规则**（上传时对每个文件执行）：
```
normalize_filename("等保三级要求.pdf")        → "等保三级要求"
normalize_filename("等保三级要求(1).pdf")      → "等保三级要求"
normalize_filename("等保三级要求（2）.pdf")    → "等保三级要求"
normalize_filename("等保三级要求副本.pdf")     → "等保三级要求"
normalize_filename("等保三级要求_副本.pdf")    → "等保三级要求"
normalize_filename("等保三级要求-副本(2).pdf") → "等保三级要求"
normalize_filename("等保三级要求v2.pdf")      → "等保三级要求v2"  (不同)
```
已入库文件与新增文件都做归一化后再比对，碰撞则标记"重名冲突"，提示覆盖/跳过/重命名。
